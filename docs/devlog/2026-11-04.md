# 2026-11-04: MVP Day 1 (foundations + resource map)

**Done:** `uv` project (Python 3.12, src layout), ruff + mypy strict + pytest/Hypothesis config, GitHub Actions CI (lint/type on Ubuntu; tests on Ubuntu + macOS), `Clock`/`RealClock`/`FakeClock`, API models (`ObjectMeta`, `Node`, `Pod`, `Deployment`), the generic resource map and the extended-resource rule (X-1/X-2), quantity parsing, architecture lint (pure `chronos.core`, no `gpu` literal in `src/`), stub entry points.

**Bug caught by a round-trip test:** quantities were serialized as bare integers, but a bare `2000` for `cpu` parses back as 2000 *cores*, not 2000 millicores. Fix: `ResourceMap` serializes canonical strings (`"2"`, `"8Gi"`, `"3"`). Lesson: an internal unit (millicores) must never leak into a format that's parsed with a different default unit.

**Surprised by:** `ruff format .` also formats Python code blocks inside Markdown, which reflowed the hand-aligned pseudocode in the ADRs. Reverted, and `docs/` is now excluded from ruff.

**Nightly profile (20 000 examples) failed twice, both test-harness problems:** a `from_regex(...).filter(...)` name strategy inside `dictionaries()` raised `FlakyStrategyDefinition` (Hypothesis couldn't replay its draws), and the 60 s per-test timeout was too short. Fixed with a composite name strategy and `make test-nightly` (`--timeout=0`). All 8 properties now pass at 20 000 examples.

**Deviation from the plan:** M1.6 said to accept ADR-0001–0004 and 0006. Accepted 0001, 0002 and 0006 only. ADR-0003 waits for pre-commit and the Makefile targets it lists (pre-commit is P0.3 in PM-1), and ADR-0004 waits for the FastAPI server (Day 3), since "Accepted" means implemented.

**Next:** Day 2, the versioned store (revisions, CAS, bind transaction with a per-resource capacity re-check, Hypothesis stateful model test).

# 2026-11-04: MVP Day 2 (versioned store)

**Done:** `chronos.store`: one global revision, CAS on `resource_version` for update / update_status / delete / bind, deep copies in and out, a `pods_on(node)` index, and `bind()` re-checking capacity for every resource name (missing name = 0). Validation: `uid` and `owner` immutable, bind-once `node_name`, `generation` bumps only on spec change, pods are created Pending and unbound. Tests: unit tests for every error path, a Hypothesis `RuleBasedStateMachine` against a dict + counter model (S1, S5), and a bind property over random resource-name sets (S2, S11). Stateful test green at the `ci` profile.

**Bug caught by the unit tests:** free capacity was computed as `capacity − (capacity + allocated)`, so every bind failed with `InsufficientCapacity`. Fixed with `sub(capacity, allocated)`.

**Mutation check:** removing the CAS check, the bind-once check or the capacity check each makes a property test fail.

**Decisions not spelled out in the plan:**
- Terminal pod phases (Succeeded/Failed) are final. A terminal pod's resources are already free for other binds, so letting it come back to Running could overcommit the node (S2).
- A node's capacity can't be lowered below what's allocated on it.
- `node.status.allocated` is computed on every read, never stored. That's part of M5.3, done early because `bind()` needs it.
- Binding doesn't bump `generation`: it's a system write, not a user spec change.

# 2026-11-04: MVP Day 3 (API, clients, heartbeats, node health)

**Done:** FastAPI server (`chronosd run`) with CRUD, status, binding, register and heartbeat routes; store errors map to 404/409/422 with a `reason` and `details` the HTTP client uses to raise the same exception. `StoreClient` protocol with `LocalStoreClient` and `HttpStoreClient` (explicit timeouts; transport errors raise `Unavailable`). In-memory heartbeat leases on the server's monotonic clock; `core/node_health.condition()`; node lifecycle controller (250 ms tick, CAS on transitions only). Tests: node-health boundary table, one contract suite run against both clients (HTTP through `httpx.ASGITransport`), HTTP status codes, lifecycle on a FakeClock. End-of-step check done with `curl` against a real `chronosd`.

**Bug caught by the contract suite:** `register()` takes capacity in internal units (cpu in millicores). Building a model from that map re-parsed a bare `4000` as 4000 *cores*, on the HTTP path and on the local client's create path. Same root cause as Day 1's round-trip bug: an internal int must never go back through the parser. Fix: hand models canonical strings (`format_resources`). Lesson: running one suite against both clients paid off on its first run.

**Decisions not spelled out in the plan:**
- A `register` endpoint (not in PLAN.md §4.4) creates the node or adopts it for a new agent epoch. Recorded in ADR-0004.
- Going NotReady revokes the node's `agent_epoch`. The old incarnation's heartbeats then get 409, so NotReady → Ready only happens through re-registration, as the state machine in PLAN.md §4.3 says.
- A node first seen without a heartbeat (e.g. created with `curl`) starts its lease when the controller first sees it, so it gets a full grace period.
- No lock around the store: route handlers are `async def`, so they run one at a time on the event loop. A lock arrives with the WAL (PM-2), when writes start to await.

**ADR-0004 → Accepted**, noting that `watch` lands in PM-3.

**Next:** Day 4, the agent and real processes.
